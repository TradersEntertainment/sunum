LIKELY QUESTIONS (your topics)
==========================================================================================
1) Why is building a heap only O(n), not O(n log n)?
   Most nodes are leaves or near the leaves, and they can sink only a few levels. Only the
   root can sink log n levels. If you add up the work level by level, it is less than 2n
   comparisons.

2) What is a min-heap?
   The same structure with the opposite rule: every parent is smaller than or equal to its
   children, so the minimum is at the root. It is used when a smaller number means a
   higher priority.

3) Why build bottom-up instead of inserting the keys one by one?
   Inserting n keys one by one (top-down) can cost n log n. Bottom-up construction costs
   only O(n).

4) AVL tree or 2-3 tree?
   Both keep the height at O(log n). AVL trees stay binary and fix the balance with
   rotations. 2-3 trees allow two keys in a node and fix overflows by splitting, so all
   leaves stay on the same level.

5) Why is Gaussian elimination Θ(n³)?
   There are three nested loops: one over the pivot rows, one over the rows below, and one
   over the columns. That gives about n³/3 multiplications.

BACKUP A1  -  The idea: transform, then conquer  (#big-idea, 4 clicks)
  [[CLICK]] We transform the problem into an easier one, then conquer it.
  [[CLICK]] There are three ways. One: instance simplification, the same problem with a
  simpler instance, like a sorted list. [[CLICK]] Two: representation change, the same
  data in a different form, like an array seen as a tree. [[CLICK]] Three: problem
  reduction, turning it into a problem we can already solve, like lcm through gcd.

BACKUP A2  -  Presorting: are all elements distinct?  (#presorting, 4 clicks)
  Example one: are all elements distinct? [[CLICK]] Brute force compares every pair, up to
  n²/2 comparisons. [[CLICK]] Presorting: sort first, then compare only neighbours,
  because duplicates end up side by side. That is n log n.
  [[CLICK]] For a million elements: 500 billion comparisons versus 20 million. Minutes
  versus a blink.
  [[CLICK]] In real life, the Unix pipeline sort | uniq works exactly like this, and so do
  databases for DISTINCT and GROUP BY.

BACKUP A3  -  Gaussian elimination: make it triangular  (#gauss, 6 clicks)
  Example two: Gaussian elimination turns a system of equations into a triangle. [[CLICK]]
  Row two minus 3/2 of row one: a zero. [[CLICK]] Row three, the same. [[CLICK]] One more
  step, and the matrix is triangular. This costs n³.
  [[CLICK]] Now we solve bottom-up: x₃ = 6, x₂ = 1, x₁ = 2. [[CLICK]] They check out.
  [[CLICK]] In real life, NumPy and MATLAB solve systems this way, and the TOP500
  supercomputers are ranked by how fast they do it.

BACKUP A4  -  Binary search trees: shape decides speed  (#bst-problem, 3 clicks)
  Now search trees. [[CLICK]] A binary search tree is fast when it is bushy. [[CLICK]] But
  if the keys arrive already sorted, it becomes a stick: search costs O(n).
  [[CLICK]] Two fixes: keep it balanced, like AVL trees, or put more keys in a node, like
  2-3 trees.

BACKUP A5  -  AVL trees: rotate to stay balanced  (#avl, 5 clicks)
  An AVL tree keeps every balance factor at −1, 0 or 1. We insert 5, 6, 8, 3, 2, 4, 7.
  [[CLICK]] After 8, node 5 tips over: one left rotation. [[CLICK]] After 2: a right
  rotation. [[CLICK]] After 4: a double rotation. [[CLICK]] After 7: another double one.
  Balanced, and still sorted.
  [[CLICK]] In real life, the Linux CPU scheduler and Java’s TreeMap use red-black trees,
  the AVL tree’s cousin.

BACKUP A6  -  2-3 trees: a full node splits in two  (#two-three, 5 clicks)
  2-3 trees take the other road: a node holds one or two keys. [[CLICK]] Three keys? The
  node splits, and the middle key moves up. [[CLICK]] Small nodes just absorb keys.
  [[CLICK]] Splits can climb to the root: the tree grows only at the top. [[CLICK]] So all
  leaves stay on one level: log n.
  [[CLICK]] In real life, every index in MySQL, PostgreSQL and SQLite is a B-tree: a 2-3
  tree with hundreds of keys per node.

BACKUP A7  -  Heaps & Heapsort  (#heap-intro, 0 clicks)
  Now the star of this chapter: heaps and heapsort. We think of the keys as a tree, but
  store them in a simple array.

BACKUP A15  -  How fast can we sort?  (#sort-bound, 2 clicks)
  If someone asks how fast sorting can be: every comparison sort needs about n log₂ n
  comparisons in the worst case (a decision tree with n! leaves has height ⌈log₂ n!⌉), and
  mergesort reaches that bound. [[CLICK]] Presorting pays off when you search many times:
  after about log₂ n searches, sorting once and using binary search wins. [[CLICK]]

BACKUP A16  -  The four AVL rotations  (#avl-rotations, 2 clicks)
  For questions about balanced trees: [[CLICK]] an AVL tree’s height is at most about 1.44
  log₂ n, and one insertion needs at most one single or double rotation, which only
  re-links a few pointers. [[CLICK]] A 2-3 tree’s height is between log₃ n and log₂ n;
  search, insert and delete are Θ(log n) in both.
