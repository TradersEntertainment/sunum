SAY (English):
  A heap is a binary tree with two rules. [[CLICK]] Rule one, shape: we fill the tree
  level by level, left to right. Only the last level can have gaps, and only on the right.

  [[CLICK]] Rule two, order: every parent is greater than or equal to its children. That
  is a max-heap.

  [[CLICK]] So keys decrease along every path down. But there is no left-to-right order: 8
  is lower, yet bigger than 4.

  [[CLICK]] Quick check: the first tree is a heap. The second has a hole in its shape. The
  third breaks the order: 6 is bigger than its parent 5.

SAY (English):

  [[CLICK]] For the node at position j, the children are at 2j and 2j + 1. For j = 2, that

  in place.

  [[CLICK]] One weakness: it is not stable. Two equal keys can change their order.

==========================================================================================
LIKELY QUESTIONS (your topics)
==========================================================================================
1) Where exactly is heapsort used in practice?
   The Linux kernel’s generic sort() in lib/sort.c is a heapsort (guaranteed n log n, no
   extra memory, no recursion). C++ std::sort and .NET Array.Sort use introsort, which
   falls back to heapsort. PostgreSQL uses a top-N heapsort for ORDER BY with a small
   LIMIT.

2) Why is building a heap only O(n), not O(n log n)?
   Most nodes are leaves or near the leaves, and they can sink only a few levels. Only the
   root can sink log n levels. If you add up the work level by level, it is less than 2n
   comparisons.

3) Heapsort, quicksort or mergesort?
   All three are n log n on average. Heapsort is in place and has no bad worst case, but
   quicksort is usually faster in practice. Mergesort is stable, but it needs an extra
   array.

4) Why is heapsort not stable?
   The root is swapped with the last key of the heap, which jumps over other keys. Two
   equal keys can end up in the opposite order, like 1a and 1b on the slide.

5) What is a min-heap?
   The same structure with the opposite rule: every parent is smaller than or equal to its
   children, so the minimum is at the root. It is used when a smaller number means a
   higher priority.

6) Why build bottom-up instead of inserting the keys one by one?
   Inserting n keys one by one (top-down) can cost n log n. Bottom-up construction costs
   only O(n).
